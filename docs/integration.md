# Интеграция модулей

## Выбранная стратегия

Использована нисходящая интеграция. Сначала был задан общий сценарий в `main.py`,
после чего к нему последовательно подключены ввод, файловый протокол, обработчик и
вывод результата. Такой порядок позволяет рано проверить полный путь данных.

## Схема взаимодействия

```text
Пользователь
    |
matrix_input.py
    |  data/matrix_request.json
matrix_processor.py
    |  data/matrix_response.json
matrix_output.py
    |
Консоль
```

`main.py` выполняет роль координатора. Обмен между модулями производится через
JSON-файлы в кодировке UTF-8. Запись выполняется во временный файл с последующим
переименованием, чтобы получатель не прочитал частично записанное сообщение.

## Контракт JSON

Запрос содержит поля `schema_version`, `matrix` и `timeout_seconds`. Ответ содержит
`schema_version`, `status`, обработанную матрицу, значения минимума и максимума,
а также номера исходных строк. Обе стороны проверяют версию схемы `1.0`.

## Обработка ошибок

- пустая, непрямоугольная матрица и нечисловые значения отклоняются;
- повреждённый JSON и несовместимая версия вызывают `ProtocolError`;
- отсутствие файла передаётся как ошибка файловой системы;
- при превышении времени обработки возникает `TimeoutError`;
- `main.py` выводит понятное сообщение и завершает работу с кодом 1.
