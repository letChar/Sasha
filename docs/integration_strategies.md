# Сравнение стратегий интеграции

| Стратегия | Плюсы | Минусы |
|---|---|---|
| Нисходящая | Рано проверяется полный пользовательский сценарий | Для нижних модулей на ранних этапах нужны заглушки |
| Восходящая | Сначала проверяются базовые функции | Полный сценарий появляется позднее |
| Сэндвич | Верхние и нижние уровни можно собирать параллельно | Сложнее согласовывать интерфейсы |
| Риск-ориентированная | Сначала проверяются самые опасные участки | Нужно заранее правильно оценить риски |
| Функциональная | Каждая функция проверяется сквозным сценарием | Порядок сборки может быть неудобным |

Для проекта выбрана нисходящая стратегия: приложение имеет один явный координатор
и короткую цепочку из четырёх модулей, поэтому полный путь данных можно проверить
раньше отдельных деталей реализации.
