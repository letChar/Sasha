# План тестирования (вариант 13)

## Цель

Проверить все модули проекта с помощью `pytest`. По варианту 13
используется анализ причинно-следственных связей. Целевое покрытие —
не менее 75 %.

## Причинно-следственные связи

| Причина | Следствие |
|---|---|
| C1: матрица непустая и прямоугольная | E1: запускается поиск экстремумов |
| C2: все элементы — конечные числа | E2: матрица принимается |
| C3: минимум и максимум в разных строках | E3: строки меняются местами |
| C4: минимум и максимум в одной строке | E4: порядок строк не меняется |
| C5: структура или числа некорректны | E5: возникает `ValueError` |
| C6: нулевой лимит времени | E6: возникает `TimeoutError` |
| C7: JSON нарушает контракт | E7: возникает `ProtocolError` |

## Основные группы автоматических тестов

| № | Проверяемая ситуация | Ожидаемый результат |
|---|---|---|
| 1 | Минимум в первой, максимум в последней строке | Первая и последняя строки меняются местами |
| 2 | Оба экстремума в одной строке | Матрица не изменяется |
| 3 | Отрицательные и дробные значения | Строки определяются по числовым значениям |
| 4 | Пустая или непрямоугольная матрица | Возникает `ValueError` |
| 5 | Повреждённый JSON или неизвестная версия | Возникает `ProtocolError` |
| 6 | Нулевой бюджет времени | Возникает `TimeoutError` |
| 7 | Полный проход ввод → JSON → обработка → вывод | Получен корректный результат |

## Команды проверки

```bash
python -m pytest -q
coverage run --branch --source=src -m pytest
coverage report --show-missing --fail-under=75
flake8 src tests
```

Тесты в `tests/test_quality.py` параметризованы по причинам C1–C7. Эти же
проверки выполняются в GitHub Actions при изменении кода и Pull Request.
